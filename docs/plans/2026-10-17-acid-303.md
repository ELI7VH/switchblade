## Pot mapping (fixed here)

`bass303` has 12 pots (0..127; WAVE 0..1; DRVTYPE 0..2). ACID's 8 edit slots plus ENV cover them like this.

| Source | Param | bass303 pot | Mapping |
|---|---|---|---|
| E0 | WAVE (SAW/SQR) | `BASS303_WAVE` | 0 / 1 as is |
| E1 | TUNE (-64..63) | `BASS303_TUNE` | pot = E1 + 64, so 0 = A4 440 Hz; 0.625 Hz per step (about +-1.6 semitones, "fine tune") |
| E2 | DECY (K4) | `BASS303_DECAY` | pot = E2. **200 ms .. 2.5 s**, exponential (`200 * 2^(n * log2 12.5)`); the donor's own range is 200 ms .. 2 s, the brief gives 2.5 s, so the one constant in `b3_set` is changed (marked) |
| E3 | ACC | `BASS303_ACCENT` | pot = E3 |
| E4 | CUT | `BASS303_CUTOFF` | pot = E4, **plus** the control-rate modulation (LFO, matrix) as fractional pot steps (below) |
| E5 | RES | `BASS303_RESO` | pot = E5 (+ the SQL offset on an accented note) |
| E6 | DRV | `BASS303_DRIVE` + `BASS303_DRVTYPE` | DRIVE pot = E6; DRVTYPE = `BASS303_DRV_SOFT` always (RAT code stays in the lifted file, unused by ACID) |
| E7 | SQL | `BASS303_ACCDEC` + a RES offset | ACCDEC pot = 7 + round(E7 * 18 / 127) (194 ms at SQL 0, the donor default, to about 600 ms at 127); on an accented note RESO pot = min(127, E5 + round(E7 * 24 / 127)). SQL 0 is therefore the donor's stock behaviour |
| ENV (K3, `P_ED_FLT`, -64..63) | | `BASS303_ENVMOD` | pot = 0 for ED_FLT <= 0, else round(ED_FLT * 127 / 63). Negative = 0 (a 303 has no negative envelope) |
| fixed | | `BASS303_VOLUME` 96, `BASS303_SLIDE` 21 (about 61 ms; the 303's 60 ms) | not exposed |

`BASS303_OS 2`, `BASS303_CTRL 4`.

Presets: `TUNE` of the placeholder was an interval in semitones (-24, -12, 7, 12 in 12 seeds); on the 303
voice it is a +-1.6 semitone fine tune, so those seeds are set to 0 (the sequence supplies the octave).
Nothing else is changed. Full re-voicing is Task 7.2 (12 presets).

## ownenv semantics (Task 5.0 hooks)

- `ownenv = 1`, `poly = 1`, `keep = 0`; the state is one `acid_t` (a `bass303_t` plus a few bytes) per part in
  the engine region (`.mem`). Zero state means "not initialised" (`rc1_c == 0`); `note_on` initialises.
  `ACID_MEM = sizeof(acid_t)`, and `<= VOID_MEM` (768): `sizeof(bass303_t)` is 752 B, so the extras must fit in 16 B.
- bass303 keeps its own VCA (amp envelope with its 1 ms / 50 ms release, the 200 Hz de-clicker, the accent boost
  of the amp). `acid_amp()` reports that VCA command, `clamp(amp_y + boost * env_y, 0, 1)` in Q15 [0, 32767]
  (clamped: `voice.c` does `env << 9`; the clamp is pinned by a test), and 32767 on a trigger that has not yet
  rendered. It reads state only (`amp()` is **not** called on the ending tick and `done()` is consulted after a kill).
- `acid_done()` returns 1 only once the VCA has reached 0: the gate is off (or the command has decayed to 0)
  **and** the quantised level is 0. A held note's VCA decays with the 303's 1.23 s time constant and reaches 0
  after about 13 s: the voice then ends, as it must (a `done()` that never fires leaks the slot). An uninitialised
  state returns 1. It is evaluated before `amp()` on every tick.
- `envq15` (the mod-matrix ENV source, ED_* and the accent cutoff boost in `voice.c`) carries this VCA command.
  ACID wants the filter envelope only from the 303's own MEG (ENVMOD), so `acid_render` takes the residual
  `m->cutoff - (envq15 * ED_FLT >> 7) - (vel > 110 ? envq15 * 24 >> 7 : 0)` = LFO and matrix cutoff only
  (the matrix clamp at +-150 steps is the only way that is not exact).
- Render applies the voice's amp ramp (`m->amp0 -> m->amp1`) **relative** to the level `amp()` reported
  (`g = amp1 / lvl`, clamped to [0, 1]), so LD_AMP, the matrix AMP and the engine-switch fade attenuate the 303 and the
  ending block (amp1 = 0, steal / shed / kill / done) ramps it to 0. On a fresh note the first block has no ramp
  (the voice's amp0 = 0 is not a fade-in; bass303's de-clicker does the onset).
- Release: `v->gate` goes 0 on note-off; `acid_render` sees the edge and calls `bass303_note_off` (an ownenv voice's
  `stage` never leaves 1, so `gate` is the only signal).
- Output scale: float +-1.0 -> Q15 (x32768), NaN/inf guarded, clamped to +-65535 (headroom for drive).

## Pitch, slide and the legato path

- Pitch is the voice's **target** pitch: `m->pitch16 + (v->pitch16 - v->pitch_cur)` (undoing `voice.c`'s own linear
  glide) plus `m->fine`, so TUNE / bend / LFO pitch arrive but the glide is bass303's own exponential slew
  (60 ms slide, tau 12 ms). `b->osc_freq` is set to it every block; modulation moves `slew_y` by the same ratio so
  it is not slewed.
- `acid_note_on` (fresh start or MONO retrigger): `bass303_note_on(note, accent = vel > 110, slide)`, where
  `slide = (t->slide_glide || P_GLIDE) && the previous note is still sounding` (bass303 gate on and VCA open).
  A MONO-mode slide (`t->slide_glide`, `seq.c:907`; the next note is on before the old one is off) is therefore a
  `bass303` slide, no retrigger.
- LEGATO (the factory presets' mode): `mono_play`'s legato branch never calls `note_on`; it only updates
  `v->note`, `v->pitch16` and *raises* `v->vel`. Two things are needed for ACID:
  1. `voice.c`: for an `ownenv` engine the legato branch **sets** `v->vel = vel` (lower as well as higher), so an
     unaccented slide target after an accented step is unaccented. One condition added, nothing changes for the ADSR
     engines (goldens unmoved, checked).
  2. `acid_render` remembers the last `(note, accent)` it applied; when `v->note` or the accent differs from that it
     is a legato event: `bass303_note_on(note, accent, slide = 1)` (slideToNote: no envelope retrigger, pitch slews),
     and, when neither `t->slide_glide` nor `P_GLIDE` is set, the slew is skipped (pitch jumps, still no retrigger).
  `t->slide_glide` is still the current step's value in the same block, so it is valid at render time.
- Test (d) drives this real path: `trk_note_on` / `trk_note_off` / `track_render` in LEGATO and in MONO.

## Tests (RED first)

`tests/acid_ref.c` builds the unmodified donor (`cc -O2 -w -ffp-contract=off -I<donor dir>`) and writes into
`tests/acid_ref/`: `grid.txt` (25 renders of a sustained C2 saw, 21 one-third-octave band levels each),
`selfosc.txt` (the resonance peak for several cutoffs at RES 127), `phrase_acc.txt` and `phrase_slide.txt`
(per-window level / centroid and per-step peaks). The vectors are committed; `acid_ref` is only re-run to
regenerate.

`tests/acid_test.c` (all through the real engine, most through `track_render`):

- (a) the 5x5 CUT/RES grid: every band within 1 dB of the reference where the reference is above -60 dB;
- (b) RES 127 self-oscillates: a peak within +-3 % of the reference frequency (and prominent);
- (c) accented step: peak >= 3 dB above the same step unaccented, higher spectral centroid, and both within the
  reference's numbers;
- (d) slide 48 -> 60 through the legato path (and MONO): pitch period shrinks monotonically over 50-70 ms
  (white-box slew and the audio's zero crossings), no amplitude dip over 1 dB; the same pair retriggered must show a
  dip (the detector can fail);
- (e) DECY 0 vs 127: the filter-envelope time (measured from the audio) differs by >= 5x, and the white-box time
  constants are 12.5x;
- (f) cost per voice <= 3x OB-Z SAW LEAD and <= 4600 instructions / sample; the measured figure is reported;
- `amp()` stays inside [0, 32767] across drive/accent/RES extremes; `done()` fires after release; ENV/LFO cutoff
  extraction; unaccented-after-accented legato; engine memory fits; a double-free / leak check (voice ends).

RED = the tests against the placeholder (NOT ownenv, no accent, not a 303). GREEN after the port.

## Goldens, budgets

Every ACID golden hash changes (the deliberate sound change; regenerated with `GOLDEN_UPDATE=1` once, diff reviewed:
no OB-Z, WAVE or DRIFT line may move; `mix` entries holding ACID, and `tests/union_golden.txt` ACID entries, may).
`cpu_baseline.txt`: the new ACID lines are appended; the old `cpu/ACID/*` lines (measured the placeholder) are not
rewritten: the controller is asked in the report. `target_budget.txt` gains `acid_render` (and `bass303_run`).
`tests/run_tests.sh` compiles with `-ffp-contract=off` so float goldens do not depend on the host's FMA.

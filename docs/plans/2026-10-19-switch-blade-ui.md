# Switch Blade: the rename, the boot logo and per-machine themes

**Date:** 2026-10-19. **Status:** plan. The open questions at the end need the user's answers before
Tasks UI.2 and UI.3.

The user asked:
- rename the firmware **Switch Blade**;
- show the Switch Blade logo, or a version of it, at boot;
- when a machine is active, colour the UI as that synth:
  - **DRIFT** (Juno-106): red, blue and black;
  - **WAVE** (the VOID WAVE port): amber and black;
  - **OB-Z:** dark, with the stripes and styling of an OB-6.

## What exists today (surveyed 2026-10-19)

**The UI is token-coloured.** Every draw call uses theme tokens (`T_BG`, `T_SURF`, `T_TEXT`,
`T_THEME`, `T_ACCENT`, and the derived `T_MID`, `T_DIM`, `T_LINE`, `T_SEL`, `T_TINT`, `T_RAISE`,
`T_KEY`, `T_INK`).
- These come from a palette of **five stored colours** (bg, surf, text, theme, accent).
  `gfx.c palette_set()` derives the rest.
- The palettes are generated by `tools/gen_ui_palettes.py`. There are 10 built-in palettes (GREY,
  GREEN, AMBER, ICE, VIOLET, ROSE, PAPER, HI-CON, NIGHT, MONO), plus one user CUSTOM palette, chosen
  in MENU > COLOR and stored in settings.
- So **a per-machine colour scheme is mostly a palette swap**: the drawing code does not change.

**The splash** (`ui_draw.c draw_splash`, shown for about 400 ms at boot while the audio already runs)
is a 176 px square in the palette's RAISE colour, with four text lines: "VOID FOUR", the version,
"Void Audio" and "on Felucca by Hügelton". It is drawn straight to the LCD, because it is larger than
the 240 × 124 canvas.

**"VOID FOUR" appears** in the splash, comments, menu titles and docs. The USB device enumerates as
"VOID FOUR".

**Budget:**
- Flash: 372,660 of 581,564 B used, so **208,904 B free**.
- RAM: .data+.bss 43,508 of 73,728 B.

## Task UI.1: rename to Switch Blade, with the boot logo

**What changes name:**
- the splash;
- the USB product string ("Switch Blade");
- the console banner (`Switch Blade v0.1`);
- MENU's INFO / FIRMWARE row;
- the release package name (`switchblade-X.Y.fwsc`) and README / HANDOVER / CLAUDE.md.

**What does not change:**
- The installer identity **`FM-1_940`**: `tools/fm1_install.py` and the update protocol key on
  `FM-1_9xx`.
- The `FOR4` storage format: existing projects and presets keep loading.
- The machine names (OB-Z, WAVE, ACID, DRIFT).
- The repo and folder name `FM1-Four`, unless the user wants that too.

**GPL attribution stays.** Felucca is GPL-3, so a small "on Felucca by Hügelton" credit line remains
on the splash and in CREDITS.md. Void Audio stays as the maker line.

**The logo pipeline:**
- The source is `assets/switchblade_logo.jpg`, the user's artwork at 2000 × 1116. A cleaner PNG
  export can replace it later; the pipeline doesn't care.
- New `tools/gen_logo.py`, run by `tools/build.py` like the fonts and icons:
  1. crop the black margins (bbox measured: 146, 39 to 1857, 1021);
  2. fit to **236 × 135** px with Lanczos;
  3. quantise to an adaptive palette with index 0 = pure black;
  4. emit `build/gen/ui_logo.h`, holding the indices as 8 bpp and the palette as RGB565.
- **Measured: 31,860 B of indices plus 256 B of palette (128 colours), about 32 KB, 15 % of the free
  flash.** RLE saves almost nothing on this art (the glows are gradients), so it is not used. A
  128-colour preview was checked by eye and holds up at 240 px.
- `draw_splash` becomes:
  1. clear to black;
  2. blit the logo row by row to the LCD, centred, in the top ~60 %. It bypasses the 240 × 124
     canvas, as the current square already does;
  3. under it, in AF_S / AF_M: the version (`v0.1`), and a dim credit line "Void Audio · on Felucca
     by Hügelton".
- **Splash timing is unchanged** (about 400 ms; the audio and the keys behave as today under it).
- **Optional, cheap:** a reveal, e.g. rows drawn top-down over the first ~150 ms, or one sparkle
  frame at the blade tip. It costs no extra flash and fits the existing splash loop. Decide by eye on
  the device.
- **The logo is drawn in its own colours**, whatever UI palette is chosen: it is artwork, not themed.

**Tests:**
- a `ui_render` screenshot of the new splash; its lint stays at 0 findings;
- static asserts on the logo header: palette length, dimensions, every index < palette length;
- the build's image size recorded;
- `four_test`, or the install test, checks that the USB product string and the identity are
  unchanged where they must be.

## Task UI.2: per-machine colour themes (the palette layer)

**Mechanism:**
- MENU > COLOR gains a first entry **MACHINE**, the new default. While it is chosen, the palette
  follows the **selected track's machine**.
- The 10 fixed palettes and CUSTOM stay. Choosing one pins it, as today, for users who want one look.
- On a track or machine change, `palette_apply()` then a full redraw (`ui.force`). That is one full
  frame, the same as a palette change in the menu today.
- Four new generated palettes, in `gen_ui_palettes.py`. The colours are starting points, tuned on
  the device:

  | Machine | bg | surf | text | theme | accent |
  |---|---|---|---|---|---|
  | **DRIFT** (Juno-106) | black | very dark warm grey | off-white | Juno red | Juno blue |
  | **WAVE** (VOID) | near-black | dark amber-brown | warm white | amber `#f5a623` (the VOID WAVE plugin's filter amber) | pale amber or white |
  | **OB-Z** (OB-6) | charcoal | dark grey | light grey | OB-6 panel blue or white | warm accent from the OB-6 legends |
  | **ACID** | ? (open question) | | | | |

- The existing `ui_render` lint (contrast, "ink on its own colour", every page × palette) runs over
  the four new palettes, so they must pass the same rules: **0 findings**.
- Settings: the stored palette value gains the MACHINE id. Old settings keep their chosen palette,
  so nothing changes for a user who picked one. Fresh settings default to MACHINE.

## Task UI.3: machine trim (the stripes and styling, beyond five colours)

Palettes give the colour scheme. The *character* the user describes (OB-6 stripes, Juno-106 styling)
needs a small decorative layer:
- a per-machine **trim** drawn on HOME's sound panel and the big EDIT page's header;
- defined as data per machine: stripe colours, widths and positions, plus an optional section-band
  colour, drawn with `lcd_fill` / `cv_rrect`;
- **no bitmaps:** a few hundred bytes per machine.

**Examples to settle with reference images:**
- **OB-Z:** the OB-6's horizontal panel stripes across the top band.
- **DRIFT:** the Juno-106's coloured section bands.

The trim must not cover values or labels; the `ui_render` alignment and lint checks guard that.

**This waits for the user's reference images** (OB-6 panel, Juno-106 panel, and any for ACID / WAVE).

## Order and cost
1. **UI.1:** rename and logo. Self-contained, about 32 KB of flash, no sound change. **Can start now.**
2. **UI.2:** machine palettes plus the MACHINE mode. Needs the ACID colours.
3. **UI.3:** trims. Needs the reference images.

(with `ui_render` at 0 findings), with no review loop (the user's standing instruction). After that
comes one build and flash, and the user judges the look on the device.
